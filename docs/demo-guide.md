# 页织四场景演示说明

这是按 [产品文档](./yezhi-product-spec.md) 做的可操作 Mock。打开首页即可使用，数据在浏览器 `localStorage`（`yezhi.demo.v1`）。工具栏「重置演示」回到种子数据。

顶栏黄字是演示模式。生成、作业、成员、提醒、权限、检查和测试统计都是模拟，不调用真实 AI，不代表真实登录，也不会自动跑回归。

## 和正式产品的差距

| 演示里有的 | 正式产品还没有的 |
| --- | --- |
| 七类节点、具体版本连线、冻结、派生、引用卡 | 真实模型、真实账号和权限系统 |
| 演示意图识别（「微调 / 补充」新版本，「派生 / 另做」新节点，否则先问） | 由模型判断意图 |
| 约 0.7 秒的演示作业，可取消、模拟失败、模拟上游更新 | 可离开页面的真实异步作业和通知 |
| 页面代码产出后单独记下构建通过、类型通过、格式失败 | 真实构建、类型检查和格式化 |
| 人工把用例标成通过 / 失败 / 未执行，统计来自这些记录 | 自动执行、自动采集和自动回归 |
| 角色下拉切换，模拟同节点一人编辑 | 多人实时光标和在线状态 |
| 撤权只写在这份演示状态里 | 真实项目授权 |

演示意图识别会在界面上标明。格式检查失败不会取消「已生成」和冻结。覆盖矩阵只数已经连上的线。

## 场景 1 · 新活动页

角色从后端周衡开始，画布是空的。右侧引导的黄按钮和画布上的手动操作走同一套状态。

1. 放入设计文档，用「微调：……」生成。产物带「演示生成 · Mock」，并记下规范 v1。
2. 放入数据接口，连到文档再生成。连上的瞬间文档还没冻结；生成成功并实际使用之后才冻结。
3. 点「模拟失败」或「取消作业」时，文档仍不冻结。
4. 提醒陈页。切换角色到陈页，在「提醒」里定位并标已处理。再切回别人，另一条提醒仍是未处理。
5. 设计师放入设计稿并生成方案①。输入「再活泼一点」会先问你要新版本还是派生。
6. 前端把设计稿连到组件资产并生成清单。清单不是可运行组件包。
7. 页面连上 `POST /join`、设计稿和组件后生成。代码一出来即成功，来源冻结。格式检查是失败，冻结不变。视觉通过 / 退回只记验收。

工具栏把规范从 v1 改成 v2 后，旧版本上的规范号不变，也不会自己重跑。

## 场景 2 · 换风格

画布上已有被线上页面用过的设计稿 a，所以 a 已冻结。

1. 对 a 提交修改。系统只能派生设计稿 b，a 的名字和内容不动。
2. b 继承 a 原来的上游版本，没有指出去的线。线上页面仍连着 a。
3. 自己新建候选页面，手动把 b 连上去再生成。不会整链复制。
4. 把线上页和候选页都「加入对比」。

## 场景 3 · 跨项目引用

用陈页打开「会员日」。资产中心能看到品牌资产里的「活动倒计时」。

1. 引用选定版本。卡片不复制正文。
2. 把引用卡连到新页面并生成。生成成功后，倒计时来源被冻结。
3. 在还能读取时，对引用卡提交「另做：……」。会派生新资产，原卡片仍指向旧版本，新节点没有下游。
4. 「撤掉我的品牌资产访问」。引用卡变成无权访问，不能再读，也不能再生成。已经生成的页面还在。需要再试派生时，先恢复访问。

顾外只能进会员日，不能引用品牌资产。

## 场景 4 · 测试上线

需求、报名接口和活动页已经生成，文档和接口因被成功使用而冻结。回归用例还是空的。

1. 把需求连到用例，再连 `POST /join` 这一项，然后生成用例。每条有稳定项 ID。
2. 把「重复报名」标为失败。上方的通过 / 失败数字只来自这些人工记录。
3. 上传报告。它是一个设计文档节点，只做关联，不往上游连线。
4. 对已冻结的报名接口提交「另做：……」，得到没有下游的新接口。旧页面和旧报告不改。
5. 下方覆盖矩阵只列出已经登记的需求、用例和页面。没有自动回归按钮。

项可以改名，旧连线还在。删除项之后，连线显示失效，不会自动改绑到名字像的另一项。冻结节点不能改名或删项。

## 检查

```bash
pnpm test:rules
pnpm typecheck
pnpm lint
pnpm build
```

`test:rules` 覆盖冻结、派生、成环、作业停止、项 ID、规范版本、提醒、编辑锁和撤权。
