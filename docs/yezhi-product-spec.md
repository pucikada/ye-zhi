# 页织产品文档：AI 原生资产中枢 + 可编排交付画布

> **讨论更新稿｜2026-11-25（Asia/Shanghai）｜尚未开发**
>
> 保留原文七大节、四个场景、七类节点及协作交付诉求，已统一第 1—20 项业务确认，核心业务核对暂告一段落。首版测试为用例生成、人工结果记录和上传报告；真实自动回归后续做。代码产出即生成成功并冻结本次实际消费的上游，检查结果独立，生成成功不等于可交付。仅技术参数、Provider 与实现细节留待实施前细化；尚未开发。

**一句话定义：以项目为单位的「AI 原生资产中枢 + 可编排交付画布」——把需求、接口、设计稿、组件、页面变成同一张依赖图上的节点与资产，让链路上的变更可追溯、可传播、可回溯。**

## 本轮已确认规则（第 1—20 项）

1. **冻结触发**：仅下游成功生成并实际使用来源节点后，来源才永久冻结。仅连线、启动、失败、取消不冻结；删出边也不恢复。
2. **冻结范围**：除画布位置、评论和提醒外全部冻结，包括名称、标签、产物、指令、附件、上游引用及具体版本；修改必须新节点，不能新增原节点版本绕过。
3. **意图判断**：未成功被消费的节点，由 AI 判断原节点新版本或派生；意图不明确先询问，不猜测执行。历史均不可覆盖。
4. **派生来源**：仅用于追溯，不凭派生关系本身冻结。新节点继承原上游引用及精确版本，但没有下游节点或出边，旧链不动；实际成功消费才冻结。
5. **生成中上游更新**：停止本次作业，询问是否基于新版重试，不自动换源或重试，停止不触发冻结。
6. **禁止环**：所有连线在建边时拦截成环，报告回流用评论、提醒和来源追溯，不建立反馈闭环。
7. **唯一边类型**：仅具体版本引用。派生是节点操作，不自动覆盖、迁移或克隆下游；人工提醒不改变依赖或自动重跑。
8. **资产展示**：一节点一条资产，历史版本收详情；派生节点为新资产，保留来源。
9. **跨画布引用**：卡片绑定选定版本，不复制内容；修改派生新资产，移除卡片不删源。
10. **归档保护**：已成功被使用的资产只能归档不可删除，保留内容及来源；删边不解冻。
11. **跨项目权限**：使用者能访问两个项目即可引用，不另需来源项目共享审批；具体动作遵守角色权限。
12. **撤权**：禁止读取源或再次用其生成；已有产物保留，来源标「无权访问」，不可用缓存、历史或导出绕过。
13. **首版测试**：生成测试用例、人工记录执行结果、上传报告；真实自动回归后续做，首版不承诺自动运行与采集。
14. **规范与检查**：生成注入项目规范，页面代码执行构建、类型、格式检查并记录；视觉由人工验收。
15. **编辑协作**：同节点同一时间一人编辑，其他人只读；不同节点可并行编辑。编辑占用不是永久冻结。
16. **提醒处理**：每个接收人独立标记已处理，不影响其他人的状态，记录保留在节点。
17. **七类能力**：七类节点均保留；按已接入能力真实生成，未接入时支持导入或手工编辑并明确标识，不冒充 AI 已生成。
18. **代码成功与冻结**：代码产出即生成成功，立即永久冻结本次实际使用的上游。构建、类型、格式检查独立记录，其失败不影响冻结；**生成成功≠可交付**，不得改成检查通过才冻结。
19. **项级身份**：采用稳定项 ID；改名保留引用，删除显示失效，不自动匹配替代项。冻结节点不能原地改名、删项或修改其他冻结字段。
20. **规范版本**：每次生成记录实际使用的规范版本；规范更新仅作用于后续生成，不修改历史、不自动重跑；同时遵守已确认的生成中引用上游更新处理规则。

## 一、背景与问题

### 1.1 现状

Web 项目的交付常经过需求文档 → 设计稿 → 接口定义 → 组件资产 → 页面实现。各环节散落在文档、Figma、接口工具、Git 和 AI 对话等位置，依赖人工转述与复制粘贴连接。

### 1.2 四大痛点

| 编号 | 痛点 | 典型表现 | 根因 |
|---|---|---|---|
| P1 | 项目协作难、资产分散 | 找人比找文件难，需求、接口、组件没有统一入口 | 缺少项目聚合与统一检索 |
| P2 | 沟通成本高、变更牵动全链 | 改一句需求，设计、接口、页面重新核对 | 依赖没有显式建模 |
| P3 | 多人习惯差异导致不一致 | 多套按钮、间距、接口命名 | 缺少统一事实源与执行机制 |
| P4 | AI 产物无法追溯 | 不清楚基于哪版需求、设计和接口，难评估变更成本 | 产物与实际生成上下文没有可查询关联 |

### 1.3 现有工具与产品机会

Figma 等擅长设计协作，文档工具擅长需求表达，接口工具擅长契约与调试，Git 和 AI 编程工具擅长实现。它们并非完全没有历史、关联或集成能力，不能把原文中的绝对化比较当作调研结论。

页织拟验证的机会是：将跨角色交付依赖、生成来源与人工变更接手放在同一工作空间，减少转述与不一致。「市场缺少这个载体」仍是产品假设。

## 二、产品定位

### 2.1 三要素

1. **资产中枢**：生成产物登记资产中心；一个节点一条资产，历史版本进详情，派生节点是有来源的新资产。
2. **编排画布**：自由连接节点，表达希望带入的上下文与依赖，不强制固定业务流水线。
3. **同源交付**：正式依赖引用来源与具体版本，不默认复制不可追溯内容；来源演进不会自动替换既有生成依据。

### 2.2 与竞品的关系

| 能力来源 | 借鉴点 | 拟验证差异 |
|---|---|---|
| FigJam 等协作画布 | 无限画布、多人协作 | 节点承载工程资产及生成依据 |
| ComfyUI 等节点工具 | 可视化编排与依赖 | 面向工程团队与人工交付接手 |
| Midjourney / Runway 等 | 变体、派生与对比 | 在交付链路上保留方案与来源 |
| Git | 历史、提交、回溯 | 非技术角色也能理解的链路视图 |

以上是借鉴方向，不是对竞品能力的完整或排他性判断。

### 2.3 五条设计原则

1. **显式优于隐式**：版本、引用、消费、冻结与采用可见。
2. **不做静默重跑**：默认由人确认是否采用新来源并执行。
3. **历史不可变**：未冻结可新版本或派生，冻结后修改必须新节点。
4. **单一事实源**：用具体来源版本表达依赖。保留来源的不可变快照不等同于无来源复制断链。
5. **链路可回溯**：能查询由谁、基于什么、生成什么、被谁成功使用。

## 三、用户与场景

### 3.1 角色

| 角色 | 画布动作 | 核心关注 |
|---|---|---|
| 产品经理 | 编需求文档、验收页面 | 需求是否准确落实 |
| 后端开发 | 生成与维护接口定义 | 契约稳定、版本和对接清晰 |
| 设计师 | 生成视觉方案、对话迭代 | 试错成本、版本与对比 |
| 前端开发 | 汇聚接口、设计和组件生成页面 | 上下文齐备、一致性、运行结果 |
| 测试 | 首版生成用例、人工记录结果、上传报告；自动回归后续做 | 已知影响范围、覆盖缺口与证据 |

### 3.2 四个核心场景

#### 场景一：从零做一个新活动页

1. 项目内新建活动页画布。
2. 后端拖入「设计文档」节点，输入需求，详情组织需求描述、接口设计、代码设计、测试点。
3. 新建「数据接口」节点，连接文档具体版本并生成接口列表；每项提供可单独连接的锚点。
4. 后端在接口节点点「提醒」，手动选择前端成员，附说明如「接口已上线，请对接页面」，确认发送。
5. 前端在项目提醒列表看到发送人、节点、说明和时间，点击定位节点；对接完成或确认无影响后手动点「已处理」，可填结果备注，各接收人独立处理且不影响他人，节点留存每人的提醒记录。
6. 设计师新建「设计稿」节点生成方案①；继续追问，AI 根据意图和冻结状态决定原节点新版本或派生②、③，意图不明确先询问。名称、标签等也遵守冻结范围。
7. 前端新建「组件资产」节点，连接选定设计稿及版本，识别轮播、图标、CTA 按钮等组件或清单。
8. 前端新建「页面」节点，连入所需接口项、选定设计稿和组件资产，注入项目规范并记录实际规范版本；产出页面代码即生成成功、冻结本次实际消费上游，再独立执行构建/类型/格式检查、人工视觉验收。生成结果不能直接冒充可交付成果。

**冻结点**：下游成功生成且实际使用某来源节点，才冻结该来源；仅连线、失败、取消、上游更新导致作业停止以及纯派生来源记录均不触发冻结。提醒可跳过，不影响依赖。生成期间所引用上游更新则停止作业并询问是否基于新版重试，不自动切换或重试；创建任何连线时拦截环。

接口定义不等于服务已上线，组件清单不等于可运行组件，低保真预览不等于构建通过。代码产出即生成成功并冻结实际使用上游；即使后续检查失败也不解冻。检查及人工视觉验收决定交付判断，不回写生成成功或冻结事实。未接入的生成能力允许导入/手工编辑，明确标识来源。

#### 场景二：给已上线页面换风格

1. 找到页面实际使用的设计稿 a 及版本。因成功消费，a 已永久冻结。
2. 对 a 提出修改要求，创建新设计稿 b；不改写 a 的原指令、名称、标签或内容。b 继承 a 原上游引用及具体版本，保留来源；这条来源记录本身不冻结 a 或 b。
3. b 初始没有下游节点或出边，原页面、依赖和线上内容不变。
4. 设计师可人工提醒前端接手；前端自行决定是否创建候选页面、选择输入并执行。不自动生成页面 b，不自动复制旧链。
5. 候选页面代码产出即生成成功并冻结实际使用上游；独立记录构建/类型/格式检查，再与线上页面并排人工视觉验收，通过交付判断后再确认发布，旧链始终不变。

派生不包含整链克隆或出边批量复制；后续若扩展此类产品能力需另立需求，不纳入本轮确认范围。

#### 场景三：跨画布复用资产

1. 用户在项目 B 的画布，从资产中心检索项目 A 的活动倒计时组件。
2. 使用者能访问 A、B 两个项目即可跨项目引用，不另需 A 项目的共享审批；编辑等操作仍遵守角色权限。
3. 在 B 中创建绑定所选版本的引用卡片，不复制源资产；修改必须派生新资产，保留来源并遵守新节点无下游/出边规则。
4. 原来源被成功消费后永久冻结；继续修改须产生新节点、新资产，原 B 链路不自动变化。
5. 生成者可人工提醒 B 接手人查看新资产；由接手人决定是否采用。系统候选更新提示另议，不默认自动待重跑。

移除 B 的引用卡片不删源资产。源资产已被成功使用后只能归档不可删除，内容及来源保留。使用者被撤权后不得读取源或再用其生成；既有产物保留，其来源显示「无权访问」，不能通过引用卡片、历史或上下文拼装绕过。

#### 场景四：测试主导的一次上线保障

**首版范围已确认**：生成用例、人工记录执行结果、上传报告。真实自动回归、自动执行进度和自动采集证据后续做，不作为首版能力。

1. 测试在需求文档 v1 下评论验收标准；评论不自动改写被冻结的正式需求。
2. 新建「测试用例」节点，连接文档，生成正常、异常、边界用例，分为功能、接口、页面组，每条有锚点。
3. 连接 `POST /join` 等接口项，补充契约及异常用例；若用例节点已冻结，修改须新节点。
4. 使用用例节点组织回归集，连接选定页面版本，可生成测试步骤、数据方案或脚本文本；不新增强制「回归集」类型，也不代表系统已执行脚本。
5. 测试人员在产品外或人工执行，首版在页织手动记录通过/失败、复现路径等结果并上传报告。若展示 46/50，明确其来源为人工记录，不伪装自动采集。真实自动回归留后续阶段。
6. 通用文档节点承接上传报告与人工执行记录，关联需求、接口、页面、用例版本；环境、构建/部署标识及证据按实际情况填写，不伪造系统采集，不新增报告节点类型。冻结报告的后续内容修改须派生新节点。
7. 开发通过来源追溯查看已知依据和疑似影响点，用评论或人工提醒反馈，不从报告向上游建立成环连线；不保证自动判断唯一应修改上游。
8. 修复冻结节点时创建新节点，继承上游引用及版本，无下游出边；接手人显式选择新来源，人工复测并另记结果/上传新报告，不触发首版自动回归。
9. 旧报告保留当时结论，不因新节点或规范更新自动改写或自动转待复测；使用评论/提醒人工协调复测，接收人各自独立处理。
10. 上线前查看已登记的需求—用例—页面关联、覆盖矩阵与风险，但不能保证关系没有遗漏或推荐集合覆盖全部风险。

测试是影响证据的重要消费者；精准回归需结合真实执行与遗漏风险验证，不是仅凭连线即可证明。首版仅用例生成、人工记录和上传报告，不能标成系统自动执行成功。真实自动回归是后续产品阶段，不是未接入即可默认补齐的首版能力。

### 3.3 场景到能力映射

| 场景 | 依赖能力 |
|---|---|
| 新活动页 | 多输入生成、规范版本、代码产出成功即冻结、独立检查、人工视觉验收 |
| 换风格 | 冻结后新节点、上游版本继承、来源记录、人工接手、对比 |
| 跨画布复用 | 双项目访问权限、固定版本引用卡片、不复制内容、修改派生、撤权处理 |
| 测试保障 | 用例生成、稳定项 ID、人工执行记录、上传报告、人工复测；自动回归后续做 |

## 四、核心概念与信息架构

### 4.1 概念模型

```text
项目 Project
 ├── 画布 Canvas（多张；跨画布以绑定选定版本的引用卡片复用）
 │    ├── 节点 Node
 │    │    └── 历史版本 NodeVersion（不可变）
 │    └── 连线 Edge（具体版本引用，可带 itemId）
 ├── 资产中心（每节点一条；历史进详情；派生为新资产）
 ├── 人工提醒及处理记录
 └── 来源、派生、成功消费及永久冻结记录
```

- 未成功消费：AI 判断原节点新版本或派生，意图不明确先询问。
- 成功生成且实际消费：来源节点永久冻结，删边不解冻。页面代码产出即成功并冻结实际消费上游；后续构建、类型、格式检查与视觉验收独立，不影响冻结。
- 冻结后修改：创建新节点，继承原上游及版本，无下游节点和出边。
- 历史不可变；冻结后除画布位置、评论和提醒外全部不可修改，包括名称、标签、产物、指令、附件和上游引用。
- 连线固定具体版本，不默认追最新；派生独立为节点操作。
- 每节点一条资产为已确认展示语义，不意味着底层数据库结构已定。
- 原 Asset=每个版本的独立列表投影不再使用；版本在节点资产详情内呈现。
- 跨画布卡片绑定所选版本，不复制源资产；修改派生新资产，移除卡片不删源。
- 派生来源只追溯，不是消费或执行连线，不单独触发冻结；所有连线必须无环，建边时拦截。
- 作业引用的上游在生成期间更新：停止、询问新版重试，不自动换源/重试、不触发冻结。每次生成保留实际规范版本，规范更新仅后续生成采用，不回改历史或自动重跑。
- 成功被使用资产只能归档、不可删除，保留内容和来源；撤权后禁止读取源和再次生成，已产物保留并标记来源无权访问。

### 4.2 七类节点

| 类型 | 承载形态 | 特有交互 |
|---|---|---|
| 设计文档 | 需求、规格、接口说明、报告等 | 折叠详情；四段式是常见组织方式，不强迫所有文档符合 |
| 数据接口 | 接口定义等可列表化内容 | 项级锚点连线 |
| 设计稿 | 视觉方案 | 对话迭代、并排对比 |
| 组件资产 | 组件或资产清单 | 自动识别、手工勾选 |
| 页面 | 页面实现及运行产物 | 预览、交付导出 |
| 图片素材 | 图片 | 替换、裁切，修改遵守冻结 |
| 测试用例 | 用例集合与回归组织 | 稳定项锚点、人工结果记录、上传报告；自动执行后续做 |

**自由连线、不预设上下游**：任意类型默认可连接，不设类型白名单；所有连线仍必须遵守无环规则，在建边时拦截自环与形成闭环的连线。类型只决定渲染、分类和少量增强；上下文与指令决定最终内容。不预设某类型只能接收或产出什么。

七类节点首版均保留，按接入能力提供真实生成；未接入支持导入或手工编辑，明确标识「AI 生成 / 导入 / 手工编辑」等实际来源和能力状态，不冒充完成生成。导入/手工修改不能绕过冻结：冻结节点改动必须派生。具体 Provider、格式解析及能力映射实施前细化，不硬编码上下游业务流。

插件化扩展为原方案保留。报告用通用文档承接；反馈通过评论、提醒和来源追溯表达，不建立成环连线。无环校验不按节点类型设白名单，也不把派生来源记录当作新的执行边。

## 五、功能需求

### 5.1 项目与画布管理

- 项目创建、归档、成员管理，角色 Owner / Editor / Commenter / Viewer。跨项目引用只需使用者能访问两个项目，无额外来源共享审批；具体动作仍遵守角色权限。
- 项目内多画布，支持重命名、复制、归档、模板化。
- 首页展示画布列表、最近资产、我的提醒；人工提醒各接收人独立处理。系统自动影响待处理不作为本轮已确认首版流程。
- 复制画布、模板中的引用与来源继承方式需明确，不能以复制绕过永久冻结。引用卡片移除不删除源资产，已成功使用的资产只可归档不可删除。

### 5.2 节点系统

#### 5.2.1 创建与输入

左侧拖入或空白处双击选择类型；输入包含自然语言指令、可选附件和上游引用。生成组合所选具体版本、适用历史与项目规范，每次生成记录实际规范版本；规范更新仅后续生成使用，不改历史、不自动重跑。AI 判断意图，但不能绕过冻结；未冻结节点意图不明确时必须先询问，不自行执行。冻结后仅位置、评论和提醒可变，其他修改均派生新节点。

#### 5.2.2 生成与状态

- 异步作业，允许离开画布，完成后可通知；失败保留先前结果，由用户决定重试。未接入能力可导入/手工编辑并明确标识，冻结节点必须派生后修改。
- 下游仅连线、生成失败、取消、作业因上游更新停止以及纯派生来源记录均不冻结来源；成功且实际使用才冻结。页面代码产出即生成成功并冻结实际消费上游，构建/类型/格式检查失败不属于生成失败，也不撤销冻结。
- 页面代码独立执行构建、类型、格式检查，分别记录结果；视觉人工验收。生成成功不等于检查通过或可交付，不以检查通过作为冻结前提。
- 空闲、生成中、错误、过期提示、编辑占用、冻结和已上线等视觉诉求保留，具体状态数据结构实施前细化，生成与检查不得混成同一成功条件。
- 所有引用本就绑定具体版本；若保留 Pin 图标，它仅为固定来源的展示，不是第二种边、成员编辑锁或永久冻结。
- 仅对可计量任务展示可靠百分比；模型无法提供真实进度时不伪造进度。
- 生成期间本次引用的上游更新，停止本次作业，询问是否基于新版重试，不自动切源/重试，停止不触发冻结。并发作业去重等实现细节实施前细化，不覆盖历史。

#### 5.2.3 详情与列表项

详情以抽屉/弹层展示产物、历史、来源、消费、实际规范版本、检查结果与提醒记录。接口和用例采用稳定 itemId，改名保留原项引用，删除项后引用提示失效，不自动匹配相似项；冻结节点不能原地改名或删项，修改必须派生。ID 格式、存储、迁移以及内容 diff 算法实施前细化，不再将已确认的稳定身份规则列为业务待定。

实际使用的取证与落库方式需细化；已确认以节点为冻结对象，不能擅自改成只冻结一个列表项。纯派生来源记录不算实际消费；下游必须成功且实际使用才冻结来源。

#### 5.2.4 版本与派生

| 情况 | 结果 |
|---|---|
| 未被成功消费，继续输入 | AI 判断原节点新版本或新节点；不明确先询问 |
| 仅建边、失败、取消、上游更新导致停止、纯派生来源 | 不触发永久冻结 |
| 下游成功且实际使用 | 来源节点永久冻结；页面代码产出即成功，不等待检查通过 |
| 页面构建/类型/格式检查失败 | 独立记录，不撤销生成成功与实际消费上游的冻结 |
| 删除出边 | 不解除已有冻结 |
| 冻结后修改 | 除画布位置、评论、提醒外均须新节点；名称、标签亦不可原改 |
| 新节点 | 继承上游具体版本；无下游节点/出边；保留来源；新资产 |

历史对比、版本树与并排展示保留；布局/文案/配色维度按产物适用，不强制三栏。冻结节点不能通过「设为当前版本/回滚」更改已冻结基线，需派生新节点；未冻结节点的历史选择交互实施前细化，画布回滚不自动改线上部署。

### 5.3 连线系统

#### 5.3.1 已确认的简化

连线只表达**具体版本引用**，可带稳定项 ID。不存在快照、覆盖、派生等第二种连线模式或落线模式选择。固定版本与来源记录保留追溯；派生是独立节点操作，不自动覆盖、迁移或克隆下游，也不因来源关系本身触发冻结。

#### 5.3.2 创建与编辑

从节点右侧或列表项锚点拖至目标左侧；显示来源、版本和项名。建边时校验全部连线无环，形成环立即拦截。删除出边不删节点、历史或成功消费事实，不解冻来源；目标已冻结时不能通过增删改其入边改变上游引用。需修改输入时派生新节点。不提供旧多模式弹窗，也不记忆旧模式来隐式执行生成。

#### 5.3.3 数据示意（非已批准 API）

```json
{
  "from": { "nodeId": "api-1", "version": 3, "itemId": "opaque-item-id" },
  "to": { "nodeId": "page-1" },
  "createdBy": "u-1024",
  "createdAt": "带时区时间戳"
}
```

消费与冻结记录独立于当前边是否存在。生成时实际用了哪些具体来源必须可追溯；作业执行清单的落库方式尚未选型。

### 5.4 影响与接手

默认：冻结来源修改 → 新节点 → 旧链不动 → 可人工提醒 → 接手人查看并决定采用 → 显式配置并生成。

**不属于当前流程**：自动追最新、自动级联标脏/重跑、旧报告自动待复测、落线即生成、派生自动整链克隆或项目开关触发无限重跑。规范更新只影响后续生成，不改变历史记录。

新旧替代关系、影响预览、内容 diff、子集批量执行与成本预览等属于未来扩展想法，不纳入本轮确认范围，不据此开发自动传播或重开已确认业务规则。

图只能证明已登记关系，不能保证没有漏连。所有连线在创建时禁止成环，报告反馈用评论、提醒和来源追溯；未来批量执行仍须另定失败停止及授权范围。生成中引用上游更新则停止询问，不以自动追最新处理。Pin、快照和忽略提示不与编辑锁混用。

### 5.5 资产中心

- 按七类资产分类，支持项目、标签、更新时间筛选；全文、标签检索保留，语义检索作为后续扩展另定范围。
- 每节点一条资产；详情展示历史版本、来源、引用位置、成功消费和变更；派生节点作为有来源的新资产。
- 复用选择具体版本，既有使用方不自动升级。跨画布使用绑定选定版本的引用卡片、不复制内容；修改派生新资产，移除卡片不删源资产。
- 跨项目使用者能访问两个项目即可引用，不另设来源共享审批；相应动作遵守角色权限。撤权后禁止读源和再次用其生成，已有产物保留、来源显示无权访问；上下文拼装和缓存不能绕过。
- 已成功被使用的资产只可归档不可删除，保留内容及来源；归档不解冻，不能以删边或移除卡片解除保护。
- 生成注入项目规范，记录每次实际使用的规范版本；规范更新仅作用于后续生成，不修改历史或自动重跑。注入不能保证 AI 必然遵守，因此页面代码执行构建、类型、格式检查，视觉人工验收。检查独立于生成成功与冻结；共享组件/Token 等具体工程组织实施前细化。

### 5.6 多人实时协作

| 能力 | 保留诉求及边界 |
|---|---|
| 在线状态 | 头像栈、带名称颜色光标 |
| 编辑占用 | 同节点一人编辑、其他人只读；不同节点并行。色环提示，租约/断线恢复参数实施前细化 |
| 生成作业 | 独立异步作业，同画布可并行 |
| 变更广播 | 新增、移动、连线、版本等同步，不自动触发下游生成 |
| 冲突处理 | 单节点编辑互斥，不同节点并行；不覆盖历史，作业去重/事务实现实施前细化 |
| 评论 | 节点、连线、区域评论与 @ 提醒 |

编辑规则已确认：同节点互斥、不同节点并行；编辑占用不等于永久冻结，冻结节点仅位置、评论、提醒可改。乐观校验、租约、作业可靠性、去重、CRDT 和状态拆分仅为实现选项；参数与架构实施前细化，不重新悬置已确认的协作方式。

#### 5.6.1 提醒与待办

发送端手动点提醒、选一个或多个成员、附说明并确认；不自动推导收件人。接收端显示发送人、节点、说明、时间，点击定位；完成或无影响后各自手动标已处理，可写备注，仅从该接收人的待处理列表移除，不影响其他接收人，节点保留每人的处理记录。

新节点可提醒旧链路接手人，不迁移依赖。多接收人独立处理已确认；数据落库和展示布局实施前细化。系统影响箱不是已确认的首版自动机制；关闭提醒不改变依赖、冻结或检查结果。

### 5.7 追溯与审计

任意节点可查有权访问的上游节点、具体版本、项级引用及派生来源。来源记录只追溯，不单独触发冻结；记录成功作业实际消费及冻结事实、实际规范版本与产物来源方式，删边不抹除。页面代码产出即成功；构建、类型、格式结果及人工视觉验收独立留痕，不回改冻结事实。人工提醒、处理与采用留痕。已使用资产只归档不可删除，保留内容来源；撤权者不得读取源或再用其生成，已有产物保留但来源标无权访问。项目可按权限导出链路报告，不能通过审计或导出绕过撤权。

### 5.8 导出与交付

页面支持预览链接、静态包、代码导出（组件代码和接口 Mock），按实际产物能力提供；Mock 不冒充生产接口。画布支持图片/PDF 与结构化 JSON 导出。

生成成功不等于可交付：代码产出时已冻结实际使用上游，随后独立记录构建、类型、格式检查及人工视觉验收。交付、预览、构建、部署及测试证据需绑定对应版本；首版测试证据为人工记录/上传报告，部署 SHA 等按真实环境关联，不伪造自动执行。真实运行生成代码或测试需隔离、限制网络/密钥/资源，具体安全沙箱未选型。数据库、对象存储、队列 Worker 等仅为技术选项，不声称页织已采用。

## 六、关键流程

### 6.1 场景一时序（13 步）

| 步 | 角色 | 动作 | 系统行为 |
|---|---|---|---|
| 1 | 后端 | 新建画布 | 建立项目内画布 |
| 2 | 后端 | 放文档、写需求 | 创建节点保存输入 |
| 3 | 后端 | 触发生成 | 成功产出 v1、登记资产 |
| 4 | 后端 | 接口节点连接文档 | 记录具体版本，仅连线不冻结 |
| 5 | 后端 | 生成接口、查看列表 | 成功实际使用文档才冻结文档；显示项锚点，可人工提醒 |
| 6 | 设计 | 建设计稿、写指令 | 创建节点 |
| 7 | 设计 | 生成① | 登记结果 |
| 8 | 设计 | 追问风格 | AI 判断意图及冻结状态；未冻结且意图不明先询问 |
| 9 | 系统 | 执行迭代 | 未冻结可新版本/新节点；冻结须新节点 |
| 10 | 设计 | 再改布局 | 同规则，新节点继承上游版本，无下游出边 |
| 11 | 前端 | 建组件资产节点 | 创建节点 |
| 12 | 前端 | 连设计稿、生成 | 成功实际消费才冻结来源 |
| 13 | 前端 | 页面汇聚多类输入并生成 | 注入并记录规范版本；代码产出即成功、冻结实际消费上游；独立构建/类型/格式检查及人工视觉验收，不以检查结果撤销冻结 |

### 6.2 换风格

```text
设计稿 a（成功被消费，永久冻结） ──具体版本──▶ 页面 a（线上）
       │
       └── 修改生成新节点、保留来源 ──▶ 设计稿 b
                                           └── 初始无下游节点/出边
人工提醒接手 → 接手人决定是否建候选页面并配置输入 → 显式生成 → 并排比较
```

原线上节点和旧链不自动替换；不自动克隆整链。派生来源箭头仅为追溯示意，不是消费连线，不单独触发冻结；新增具体版本引用均先校验无环。

### 6.3 冻结来源修改后的流转

```text
对冻结节点提出修改
 → AI 判断意图并遵守冻结约束
 → 创建新节点，继承原上游引用及具体版本
 → 不继承下游节点/出边，保留派生来源，新资产登记
 → 生成；若引用上游更新则停止询问新版重试，不自动换源或重试
 → 产物成功后按实际消费冻结上游；页面代码产出即成功，无需等待检查
 → 页面独立记录构建/类型/格式检查与人工视觉验收，不回改冻结事实
 → 旧节点、旧报告、旧链不变
 → 生成者可人工提醒
 → 接手人查看并决定采用，显式配置输入与生成
 → 下游成功且实际使用新节点后，新节点永久冻结
```

生成失败、取消、仅连线、纯派生来源记录和因上游更新停止均不触发该次冻结，也不会解除已有成功消费形成的冻结。代码已产出后的检查失败不属于这里的生成失败，不撤销冻结。全流程建边禁止成环；报告回流用评论、提醒和来源追溯。

## 七、交互与视觉规范

### 7.1 节点状态视觉

| 状态/标识 | 视觉意图与边界 |
|---|---|
| idle | 常规卡片与版本号 |
| generating | 骨架、取消、流光；可靠时才展示百分比 |
| 人工待处理 | 根据个人未处理提醒展示，不自动推导全链标脏；潜在影响视图属后续扩展 |
| 生成失败 | 原因与人工重试入口，保留旧结果，不新增成功消费冻结 |
| 检查失败 | 构建/类型/格式分别记录；代码已生成成功和上游冻结不撤销，提示尚不可据此交付 |
| 编辑占用 | 头像色环、成员提示；同节点他人只读，不同节点并行，不等于永久冻结 |
| 永久冻结 | 明示已被成功使用；仅位置、评论、提醒可改，其他字段冻结；可查消费来源 |
| 已停止/待询问 | 引用上游在生成中更新，停止并询问新版重试；不自动重试、不触发冻结 |
| 来源无权访问 | 撤权后保留已产物与来源标识，禁止读取源或再次用其生成 |
| 已上线 | 明确对应交付版本，不自动随画布更新 |
